SECTION 1 — FONTS
================================================================================

Three fonts in this project. Use them correctly:

  DM Sans        → body text, paragraphs, descriptions, form labels, nav items
  Plus Jakarta Sans → headings, page titles, card titles, stat numbers
  Yatra One      → ONLY for the Nepali logo text "कर्म" in the sidebar header

They are loaded in index.html already. Use them via Tailwind like:

  font-sans  → DM Sans (already set as default in tailwind config)
  font-heading → Plus Jakarta Sans  (add this as a custom font family if not set)

For the AI: whenever you write a page title or section heading, use:
  <h1 className="font-heading text-2xl font-bold ...">
  <h2 className="font-heading text-xl font-semibold ...">

For body text, labels, descriptions — just leave it (DM Sans is default):
  <p className="text-sm text-slate-600 dark:text-slate-400">

NEVER use system fonts or Arial or Inter. The fonts are already loaded.

SECTION 6 — DARK MODE RULES (non-negotiable)
================================================================================

ALWAYS pair these:
  bg-white          → dark:bg-slate-800
  bg-slate-50       → dark:bg-slate-900
  bg-slate-100      → dark:bg-slate-800
  text-slate-900    → dark:text-slate-100
  text-slate-700    → dark:text-slate-300
  text-slate-600    → dark:text-slate-400
  text-slate-500    → dark:text-slate-500
  text-slate-400    → dark:text-slate-500
  border-slate-200  → dark:border-slate-700
  border-slate-100  → dark:border-slate-700

NEVER write a Tailwind color class without its dark: pair.
The toggle is stored in localStorage and applied to <html> by the theme toggle.
Tailwind dark mode is class-based: class="dark" on <html>.
Make sure tailwind.config has: darkMode: 'class'

================================================================================
SECTION 7 — RESPONSIVE RULES
================================================================================

This app is sidebar-based. The sidebar handles responsiveness:
  Desktop (lg+): sidebar visible, pages have normal padding
  Tablet (md):   sidebar collapses to icon-only
  Mobile (sm):   sidebar hidden, hamburger opens overlay drawer

Your pages do NOT need to handle sidebar behavior.
But your page content should be responsive:

  - Use grid-cols-1 md:grid-cols-2 lg:grid-cols-3 for card grids
  - Use flex-col sm:flex-row for action rows that stack on mobile
  - Use text-xl md:text-2xl for headings that scale
  - Avoid fixed widths — use max-w + w-full
  - Padding: p-4 on mobile, p-6 on desktop: className="p-4 md:p-6"
  - Images in cards: set explicit heights so they don't collapse on mobile
    (h-48 md:h-64 for hero images, h-20 w-20 for thumbnails)

================================================================================
SECTION 8 — THINGS TO NEVER DO
================================================================================

  ✗ No gradients anywhere (no bg-gradient-to-*, no gradient text)
  ✗ No box shadows for decoration (no shadow-xl, shadow-2xl on cards)
      Only shadow-sm allowed on hover states: hover:shadow-sm
  ✗ No animations except: animate-spin (spinner), animate-pulse (skeleton),
      transition on hover (transition, hover:bg-X)
  ✗ No fixed pixel font sizes (no style="font-size: 24px") — use Tailwind text-*
  ✗ No inline style= for colors — always Tailwind classes
  ✗ No absolute positioning for layout — only for floating buttons (AI assist)
  ✗ No z-index hacks
  ✗ No !important
  ✗ No rounded-full on rectangular cards — only on pills, avatars, badges
  ✗ No bright/neon accent colors — violet is the ONLY accent
  ✗ No emojis in UI (except the category icons from DB which are emoji strings)
  ✗ No placeholder Lorem Ipsum text — write real Nepal-appropriate placeholder text
      e.g. "Last seen near Thamel, Kathmandu" not "Lorem ipsum dolor..."
  ✗ No hardcoded English-only text — run all static strings through useTrans()

================================================================================
SECTION 9 — WRITING useTrans() CORRECTLY
================================================================================

The i18n system is custom. Here is how to use it:

  import { useTrans } from '../i18n'
  const { t } = useTrans()

  // Then in JSX:
  <h1>{t('pageTitle')}</h1>
  <button>{t('postAlert')}</button>

  // To add a new translation, go to src/i18n/index.ts and add:
  en: {
    ...existing keys...
    postAlert: 'Post Alert',
    findTheLost: 'Find The Lost',
    backButton: 'Back',
    verifyIdentity: 'Verify Identity',
    submitDocuments: 'Submit for Verification',
    underReview: 'Your documents are under review',
    verified: 'Identity Verified',
  },
  np: {
    ...existing keys...
    postAlert: 'सूचना पोस्ट गर्नुहोस्',
    findTheLost: 'हराएको खोज्नुहोस्',
    backButton: 'फिर्ता',
    verifyIdentity: 'परिचय प्रमाणित गर्नुहोस्',
    submitDocuments: 'प्रमाणीकरणका लागि पेश गर्नुहोस्',
    underReview: 'तपाईंका कागजात समीक्षामा छन्',
    verified: 'परिचय प्रमाणित',
  }

  For page titles and main labels, always use t(). For dynamic content
  (names, locations, descriptions from DB) — just use the value directly,
  it's user-generated and not translated.
